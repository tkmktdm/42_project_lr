## 考え方

- シェルスクリプトで `.c` → `.o` → `libft.a` の3ステップを行う
- `-c` フラグでリンクせずオブジェクトファイルだけ生成する
- `ar rc` でオブジェクトをアーカイブ、`ranlib` でインデックスを付与

### 用語メモ

- **静的ライブラリ（.a）**: コンパイル時にリンクして使う関数の塊。`ar`（archiver）で作る
- **`ar rc`**: `r`=追加・置換、`c`=アーカイブが存在しなければ作成
- **`ranlib`**: アーカイブ内のシンボルテーブルを更新するコマンド
- **`-c` フラグ**: コンパイルのみ行い、リンクしない（`.o` ファイルを作る）

---

## メモリ図解

```
libft_creator.sh の処理フロー

  ① cc -Wall -Wextra -Werror -c *.c
       ↓
  ft_putchar.o  ft_swap.o  ft_putstr.o  ft_strlen.o  ft_strcmp.o

  ② ar rc libft.a ft_putchar.o ft_swap.o ft_putstr.o ft_strlen.o ft_strcmp.o
       ↓
  libft.a ─────────────────────────────────
  │ ft_putchar.o │ ft_swap.o │ ft_putstr.o │ ...
  ─────────────────────────────────────────

  ③ ranlib libft.a  → シンボルテーブル更新
```

---

## 解答コード

```bash
cc -Wall -Wextra -Werror -c ft_putchar.c ft_swap.c ft_putstr.c ft_strlen.c ft_strcmp.c
ar rc libft.a ft_putchar.o ft_swap.o ft_putstr.o ft_strlen.o ft_strcmp.o
ranlib libft.a
```

**なぜそう書くか**

| コード | 理由 |
|--------|------|
| `-c` フラグ | `.o` を作るだけでリンクしない。`main` がなくてもエラーにならない |
| `ar rc` | 既存の `libft.a` に追加・作成する |
| `ranlib` | `ld` がシンボルを高速に見つけられるようにする |

---

## ハマりポイント

### ❌ NG: `-c` を忘れる

```bash
cc -Wall -Wextra -Werror ft_putchar.c ft_swap.c ...
# → main がないのでリンクエラー or a.out が作られて .o が生成されない
```

→ `ar` の次のステップで `.o` が見つからず失敗する

---

### ❌ NG: `ranlib` を省略する

```bash
ar rc libft.a *.o
# ranlib なし
```

→ 環境によってはリンク時にシンボルが解決されないことがある
