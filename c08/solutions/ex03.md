## 考え方

- `struct` に `typedef` を組み合わせると `struct s_point` の代わりに `t_point` と書ける
- プロトタイプだけ書けばよい（実装は `ft_point.h` に書かない）
- PDFのmainが正しくコンパイルできれば正解

### 用語メモ

- **struct**: 複数の変数をひとまとめにするデータ型。`struct s_point { int x; int y; };`
- **typedef**: 型に別名。`typedef struct s_point t_point;` で `t_point` が型名になる
- **ポインタ渡し**: `set_point(t_point *point)` の `*point` は「t_point のアドレスを受け取る」。関数内で `point->x` で変更できる

## 解答コード

```c
#ifndef FT_POINT_H
# define FT_POINT_H

typedef struct s_point
{
    int x;
    int y;
}           t_point;

void    set_point(t_point *point);

#endif
```

**なぜそう書くか**

| コード | 理由 |
|--------|------|
| `typedef struct s_point { ... } t_point;` | `t_point point;` と短く書けるようになる |
| `void set_point(t_point *point);` | ポインタ渡しにする理由: 関数内で構造体の値を変更するため |

## ハマりポイント

### ❌ NG: メンバ名のスペース

```c
typedef struct s_point
{
    int     x;
    int     y;  // Norminette: メンバのアライメントを揃えなくてよい（揃えてもOK）
}       t_point;
```

→ Norminette のアライメントルールは構造体内メンバにも適用される。タブで揃えること

---

### ❌ NG: typedef なし

```c
struct s_point { int x; int y; };
void set_point(struct s_point *point);  // NG: typedef がないと t_point が使えない
```

→ PDFのmainが `t_point point;` と書いているので `typedef` 必須

---

### ❌ NG: set_point の実装をヘッダに書く

```c

{
    point->x = 42;  // ヘッダに実装を書いてはいけない

```

→ プロトタイプ（宣言）だけでよい。実装は `.c` ファイルに書く
