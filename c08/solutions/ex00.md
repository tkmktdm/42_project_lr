# ex00 — ft.h

## 要件メモ

| 項目 | 内容 |
|------|------|
| ファイル名 | `ft.h` |
| 提出先 | `ex00/` |
| 使える関数 | None |
| やること | 5つの関数プロトタイプをまとめたヘッダファイルを作成 |

---

## 考え方

- ヘッダファイルは「関数の宣言（プロトタイプ）」だけを書く場所
- 実装（定義）はここに書かない
- 二重インクルード防止のため **インクルードガード** が必須

### 用語メモ

- **プロトタイプ**: 関数の名前・引数・戻り値の型だけ書いた宣言。実装は別の `.c` に書く
- **インクルードガード**: `#ifndef / #define / #endif` の組み合わせ。複数回 `#include` されても一度しか展開されないようにする

---

## メモリ図解

```
コンパイル時のイメージ:

main.c ──── #include "ft.h" ────► プロトタイプが展開される
                                    void ft_putchar(char c);
                                    void ft_swap(int *a, int *b);
                                    void ft_putstr(char *str);
                                    int  ft_strlen(char *str);
                                    int  ft_strcmp(char *s1, char *s2);

実装 (ft_putchar.c など) と main.c を一緒にリンクして実行ファイル完成
```

---

## 解答コード

```c
#ifndef FT_H
# define FT_H

void    ft_putchar(char c);
void    ft_swap(int *a, int *b);
void    ft_putstr(char *str);
int     ft_strlen(char *str);
int     ft_strcmp(char *s1, char *s2);

#endif
```

**なぜそう書くか**

| コード | 理由 |
|--------|------|
| `#ifndef FT_H` | ガード名は慣習的にファイル名を大文字・アンダースコアに変換したもの |
| `# define FT_H` | Norminette 準拠: `#` の後にスペース（インデント付き `#`） |
| `void ft_putchar(char c);` | セミコロン必須。プロトタイプは宣言なので `;` で終わる |
| `#endif` | `#ifndef` と対応。必ずセットで書く |

## ハマりポイント

### ❌ NG: インクルードガードなし

```c
void    ft_putchar(char c);
/* ... */
```

→ 同じヘッダを複数回インクルードすると「再定義」エラーになる可能性がある

---

### ❌ NG: 実装をヘッダに書く

```c
void    ft_putchar(char c)
{
    write(1, &c, 1);  // 実装はヘッダに書かない
}
```

→ 複数ファイルでインクルードすると多重定義エラーになる

---

### ❌ NG: Norminette の `#` ルール

```c
#ifndef FT_H
#define FT_H   // ← スペースなし、Norminette エラー
```

→ `# define FT_H`（`#` と `define` の間にスペース1つ）が正しい
