# ex01 — Makefile

## 要件メモ

| 項目 | 内容 |
|------|------|
| ファイル名 | `Makefile` |
| 使える関数 | なし |
| ソースの場所 | `srcs/` ディレクトリ |
| ヘッダの場所 | `includes/` ディレクトリ（`ft.h`） |
| ルール | `all`, `clean`, `fclean`, `re`, `libft.a` |
| やること | `libft.a` をビルドする Makefile |

---

## 考え方

- `.o` は `srcs/` に生成する（`.c` と同じ場所）
- `libft.a` はルート（Makefile と同じ場所）に生成する
- 不要な再コンパイルをしない（依存関係が正しく設定されている）
- `make` と `make all` と `make libft.a` はすべて同じ動作

### 用語メモ

- **`.c.o`（サフィックスルール）**: `foo.c` → `foo.o` を生成する汎用ルール
- **`$<`**: ルールの最初の依存ファイル（`.c` ファイル）
- **`$@`**: ターゲット名（`.o` ファイル）
- **`.PHONY`**: ファイル名と競合しないようにターゲットを「仮想」と宣言する

## 解答コード

```makefile
CC      = cc
CFLAGS  = -Wall -Wextra -Werror
SRCS    = ft_putchar.c ft_swap.c ft_putstr.c ft_strlen.c ft_strcmp.c
SDIR    = ./srcs/
IDIR    = ./includes/
NAME    = libft.a
OBJS    = ${addprefix ${SDIR}, ${SRCS:.c=.o}}

all: ${NAME}

.c.o:
	${CC} ${CFLAGS} -c -I ${IDIR} $< -o $@

${NAME}: ${OBJS}
	ar rc ${NAME} ${OBJS}
	ranlib ${NAME}

clean:
	rm -f ${OBJS}

fclean: clean
	rm -f ${NAME}

re: fclean
	$(MAKE) all

.PHONY: all clean fclean re
```

**なぜそう書くか**

| コード | 理由 |
|--------|------|
| `OBJS = ${addprefix ${SDIR}, ...}` | `.o` を `srcs/` 配下に生成するためパスを付与 |
| `.c.o` ルール | 各 `.c` を個別に `.o` にコンパイルするパターンルール |
| `$@` | ターゲットのパス（`srcs/ft_putchar.o`）が正しく入る |
| `fclean: clean` | 依存関係にすることで clean の処理を再利用 |
| `$(MAKE) all` | re ルールで fclean 後に正しく all を実行させる |
| `.PHONY` | `all` などと同名ファイルがあっても誤作動しない |

## ハマりポイント

### ❌ NG: `all:` にレシピを書く

```makefile
all:
	${NAME}   # ← "libft.a" というコマンドを探してエラー
```

→ `all: ${NAME}` と依存関係として書く

---

### ❌ NG: `fclean` で clean をレシピとして呼ぶ

```makefile
fclean:
	clean        # ← シェルは "clean" というコマンドを探す
	rm -f ${NAME}
```

→ `fclean: clean` と依存関係にする

---

### ❌ NG: OBJS にパスを付けない

```makefile
OBJS = ${SRCS:.c=.o}  # → ft_putchar.o（srcs/ なし）
```

→ `.o` が srcs/ 以外に生成される。PDF 違反

---

### ❌ NG: `cc` の代わりに `gcc` を使う

PDF に「`cc` を使用します」と明記されている
