## 考え方

- C には `bool` 型がない（C99以前）ので `enum` で自前定義する
- `EVEN(nbr)` マクロ: 偶数判定は `nbr % 2 == 0`
  - `(nbr) % 2` は偶数で `0`（falsy）、奇数で `1`（truthy）
  - 偶数のとき TRUE を返すには `(((nbr) % 2) == 0 ? TRUE : FALSE)` が正しい

### 用語メモ

- **enum**: 列挙型。整数の定数に名前をつける仕組み。`false=0, true=1` と対応
- **typedef**: 型に別名をつける。`typedef enum e_bool { false, true } t_bool;` で `t_bool` という型名が使える
- **関数マクロ**: 引数をとる `#define`。副作用に注意（引数を複数回評価しないこと）

---

## EVEN マクロの正しい実装

```
EVEN(0) → 0 % 2 == 0 → TRUE   ✅ 偶数
EVEN(1) → 1 % 2 == 0 → FALSE  ✅ 奇数
EVEN(2) → 2 % 2 == 0 → TRUE   ✅ 偶数
EVEN(4) → 4 % 2 == 0 → TRUE   ✅ 偶数
```

**注意**: `(((nbr) % 2) ? TRUE : FALSE)` は **逆**になる（奇数でTRUE）

## 解答コード

```c
#ifndef FT_BOOLEAN_H
# define FT_BOOLEAN_H

# include <unistd.h>

void    ft_putstr(char *str);

# define EVEN(nbr)  (((nbr) % 2 == 0) ? (TRUE) : (FALSE))

# define EVEN_MSG   "I have an even number of arguments.\n"
# define ODD_MSG    "I have an odd number of arguments.\n"

# define TRUE       1
# define FALSE      0
# define SUCCESS    0

typedef enum e_bool
{
    false,
    true
}           t_bool;

#endif
```

**なぜそう書くか**

| コード | 理由 |
|--------|------|
| `(((nbr) % 2 == 0) ? TRUE : FALSE)` | 偶数 → TRUE を返す正しい論理 |
| `(nbr)` を括弧で囲む | `EVEN(a + b)` のような式でも正しく展開される |
| `# define` のスペース | Norminette `-R CheckDefine` 準拠 |

## ハマりポイント

### ❌ NG: EVEN マクロの論理逆

```c
# define EVEN(nbr) (((nbr) % 2) ? (TRUE) : (FALSE))
```

→ `nbr % 2` は奇数で `1`（truthy）なので、奇数のとき TRUE になってしまう  
→ `EVEN(2)` = `(0 ? TRUE : FALSE)` = FALSE ← **偶数なのにFALSE**

---

### ❌ NG: マクロ引数を括弧で囲まない

```c
# define EVEN(nbr) (nbr % 2 == 0 ? TRUE : FALSE)
```

→ `EVEN(a | b)` などで `|` の優先順位が `%` より低くバグになる

---

ヘッダファイルの `#define` は `-R CheckDefine` フラグで追加チェックされる。  
`norminette ft_boolean.h` だけでは通っても、Moulinette では `-R CheckDefine` で落ちることがある。
