# ex03 — ft_sort_params

## 要件メモ

| 項目 | 内容 |
|------|------|
| ファイル名 | `ft_sort_params.c` |
| プロトタイプ | `int main(int ac, char **av)` |
| 使える関数 | `write` のみ |
| 禁止 | グローバル変数、`printf` など |
| やること | `argv[0]` 以外の引数を ASCII 順にソートして1行に1つずつ出力 |

---

## 考え方

- 文字列の比較には `ft_strcmp` を自前実装する（`string.h` の `strcmp` は使えない）
- ソートアルゴリズムはバブルソートまたは選択ソートが Norminette 的に書きやすい
- `ft_strcmp` の戻り値の符号だけが重要（正なら s1 > s2、負なら s1 < s2、0なら等しい）

### 用語メモ

- **ASCII順**: 数字 < 大文字 < 小文字 の順。`'A'=65`, `'Z'=90`, `'a'=97`, `'z'=122`
- **バブルソート**: 隣接する要素を比較・交換しながらソートする方法。O(n²)

---

## メモリ図解

```
./a.out banana apple cherry で実行した場合
argc = 4

  argv（ポインタ配列）
  av[1] → "banana"
  av[2] → "apple"
  av[3] → "cherry"

  バブルソート1パス目:
  "banana" vs "apple"  → 'b'(98) > 'a'(97) → swap
  av[1]="apple", av[2]="banana"

  "banana" vs "cherry" → 'b'(98) < 'c'(99) → no swap

  バブルソート2パス目:
  "apple" vs "banana"  → 'a' < 'b' → no swap
  "banana" vs "cherry" → 'b' < 'c' → no swap

  最終: apple / banana / cherry
```

## 解答コード（正しいバブルソート実装）

```c
#include <unistd.h>

void    ft_putchar(char c)
{
    write(1, &c, 1);
}

int     ft_strcmp(char *s1, char *s2)
{
    while (*s1 && *s1 == *s2)
    {
        s1++;
        s2++;
    }
    return (*s1 - *s2);
}

void    ft_sort_params(int ac, char **av)
{
    int     i;
    int     j;
    char    *tmp;

    i = 1;
    while (i < ac - 1)
    {
        j = 1;
        while (j < ac - i)
        {
            if (ft_strcmp(av[j], av[j + 1]) > 0)
            {
                tmp = av[j];
                av[j] = av[j + 1];
                av[j + 1] = tmp;
            }
            j++;
        }
        i++;
    }
}

int     main(int ac, char **av)
{
    int i;
    int j;

    ft_sort_params(ac, av);
    i = 1;
    while (i < ac)
    {
        j = 0;
        while (av[i][j] != '\0')
        {
            ft_putchar(av[i][j]);
            j++;
        }
        ft_putchar('\n');
        i++;
    }
    return (0);
}
```

**行ごとメモ**

| コード | なぜそう書くか |
|--------|---------------|
| `ft_strcmp` | `string.h` 禁止のため自前実装。等しい間ポインタを進め、差を返す |
| `j < ac - i` | バブルソートの最適化。i パス目では末尾 i 個はすでにソート済み |
| `av[j]` と `av[j+1]` を比較 | 隣接要素を比較・交換するバブルソートの基本操作 |
| `av[i][j] != '\0'` | インデックス `j` で文字列を走査する正しい終端判定 |

## ハマりポイント（提出コードの既知バグ）

### ❌ バグ1: デバッグ用 printf が残っている

```c
#include <stdio.h>  // ← 禁止
...
printf("%s vs %s: %d\n", av[i], av[j], ft_strcmp(av[i], av[j]));  // ← 禁止
```

→ `write` のみ許可。`nm -u` で `printf` が検出され、禁止関数チェックに失敗する

---

### ❌ バグ2: ソートアルゴリズムのロジックミス

```c
// 提出コードのソート
i = 1;
while (i < ac - 1)       // i: 1 から ac-2
{
    j = 1;
    while (j < ac)        // j: 1 から ac-1（j が i より前の要素も参照）
    {
        if (ft_strcmp(av[i], av[j]) > 0)
            swap(av[i], av[j]);
        j++;
    }
    i++;
}
```

→ `j = 1`（`i` より前の要素）から比較するため、前の反復でソートした結果を破壊する可能性がある  
→ `j = i + 1` から始めるか、バブルソートで隣接要素 `av[j]` vs `av[j+1]` を比較すべき

---

### ❌ バグ3: main の出力ループ条件が誤り

```c
while (j < av[i][j])  // ← av[i][j] は文字の ASCII 値（数値）であって長さではない
```

→ 正しくは `av[i][j] != '\0'`。文字の ASCII 値を上限にすると、短い文字列では途中で止まり、長い文字列では文字列外メモリを読み込む（未定義動作）
