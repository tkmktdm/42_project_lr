# ex02 — ft_rev_params

## 要件メモ

| 項目 | 内容 |
|------|------|
| ファイル名 | `ft_rev_params.c` |
| プロトタイプ | `int main(int ac, char **av)` |
| 使える関数 | `write` のみ |
| 禁止 | グローバル変数、`printf` など |
| やること | `argv[0]` 以外の引数を**逆順**に1行に1つずつ出力 |

---

## 考え方

- `av[ac-1]` から始めて `av[1]` まで、末尾から出力していく
- `ac` をデクリメントしながら `i <= ac - 1` の条件でループ制御
- `i = 1` は「最後まで出力したかどうか」の番兵として使う（`ac` が 1 になった時点で `i <= 0` で停止）

### 用語メモ

- **逆順**: `av[ac-1]` が最後の引数、`av[1]` が最初の引数

---

## メモリ図解

```
./a.out test1 test2 test3 で実行した場合
argc = 4

  argv
  av[0] → "./a.out"   ← 出力しない
  av[1] → "test1"     ← 3番目に出力
  av[2] → "test2"     ← 2番目に出力
  av[3] → "test3"     ← 1番目に出力（ac-1 = 3 から開始）

  ループの流れ:
  i=1, ac=4: 1 <= 3 → av[3]="test3" を出力 → ac=3
  i=1, ac=3: 1 <= 2 → av[2]="test2" を出力 → ac=2
  i=1, ac=2: 1 <= 1 → av[1]="test1" を出力 → ac=1
  i=1, ac=1: 1 <= 0 → ループ終了
```

---

## 解答コード

```c
#include <unistd.h>

void    ft_putchar(char c)
{
    write(1, &c, 1);
}

int     main(int ac, char **av)
{
    int i;

    i = 1;
    while (i <= ac - 1)
    {
        while (*av[ac - 1] != '\0')
        {
            ft_putchar(*av[ac - 1]);
            av[ac - 1]++;
        }
        ft_putchar('\n');
        ac--;
    }
    return (0);
}
```

**行ごとメモ**

| コード | なぜそう書くか |
|--------|---------------|
| `i = 1` | 停止条件の番兵。`i` は変化しない |
| `while (i <= ac - 1)` | `ac` が 1 になった時（引数がすべて出力済み）に停止 |
| `*av[ac - 1]` | 末尾の引数から出力開始 |
| `av[ac - 1]++` | 末尾引数のポインタを1文字進める |
| `ac--` | 次のイテレーションで1つ前の引数を見るために `ac` を減らす |

## ハマりポイント

### ❌ NG: i をインクリメントして終了条件にする

```c
i = ac - 1;
while (i >= 1)   // 逆順インデックスを使う別パターン
{
    ...
    i--;
}
```

→ これ自体は正しいが、提出コードは `ac` をデクリメントする方式を採用。
どちらも正解だが混在させるとバグの元

---

### ❌ NG: 引数なしで `av[ac-1]` にアクセス

```c
// ac == 1 の場合
while (i <= ac - 1)  // 1 <= 0 は false → ループに入らない ✓
```

→ 条件が正しければ引数なしでも安全。ただし順序を間違えると `av[0]` が誤って出力される

---

### 引数なしの挙動

```
./a.out （引数なし）
   argc = 1
   i = 1, 条件 1 <= 0 は false → ループに入らない → 何も出力されない ✓
```
