## 第 I 章 まえがき

デジタル時代には、庭にさえスマートなシステムが必要である。

ある賢明な園芸家はこう言った。「花を植えておいて、根の様子を見るために毎日引き抜くことはできない」。コードも同じである。最も美しい成長は、過程を信頼し、プログラムを一層ずつ自然に育てていくときに生まれることがある。

活気あるコミュニティガーデンの裏には、関係性のネットワークがある。植物は孤立して育つのではない。共通の必要を分かち合いながら、それぞれの種が固有の何かをもたらすコミュニティを形成している。害虫から他の植物を守るものもあれば、土壌に窒素を固定するものも、繊細な苗に日陰を作るものもある。この相互扶助の網の目は、優れた設計のソフトウェアシステムの動きによく似ている。個々のコンポーネントが明確な役割を持ち、調和して協働するのである。

熟練の園芸家が健康な土は健康な植物を育てると知っているように、経験豊富なプログラマは、よく構造化されたコードが堅牢なアプリケーションへ成長することを理解している。コードの整理は庭の設計に似ていると気づくだろう。保護が必要な要素もあれば、成長の余地が必要な要素もある。そして最良のシステムは、すべてにふさわしい場所と目的があるときに生まれる。

このプロジェクトでは、コミュニティガーデンの発展に実際に役立ちうるツールを作りながら、プログラミングのスキルを育てる。あなたが書く一行一行のコードは、可能性というデジタルの土壌に植えられた種である。

## 第 II 章 AI に関する指示

### 背景

学習の過程で、AI はさまざまな作業の助けになる。AI ツールの多様な能力と、それが自分の作業をどう支えられるかを時間をかけて探ること。ただし、常に慎重に扱い、結果を批判的に評価すること。コード、ドキュメント、アイデア、技術的な説明のいずれであっても、自分の質問が適切だったか、生成された内容が正確かを完全に確信することはできない。仲間は、ミスや見落としを避けるための貴重な存在である。

### 主なメッセージ

- AI を使って、繰り返しの作業や面倒な作業を減らす。
- 将来のキャリアに役立つプロンプト技術を、コーディング、非コーディングの両面で伸ばす。
- AI の仕組みを学び、よくあるリスク、偏り、倫理的な問題を予測して避けられるようにする。
- 仲間と協力しながら、技術力とパワースキルの両方を伸ばし続ける。
- **自分が完全に理解し、責任を持てる AI 生成物だけを使う。**

### 学習者のルール

- 時間をかけて AI ツールを試し、その仕組みを理解すること。そうすることで倫理的に使い、偏りを減らせる。
- プロンプトを書く前に問題について考えること。そうすることで、正確な用語を使った、より明確で詳しく適切なプロンプトを書ける。
- AI が生成したものはすべて、体系的に確認、見直し、疑問視、テストする習慣をつけること。
- 必ず仲間のレビューを受けること。自分だけの検証に頼らないこと。

### このフェーズの成果

- 汎用的なプロンプト技術と、特定分野に特化したプロンプト技術を伸ばす。
- AI ツールを効果的に使って生産性を高める。
- 計算論的思考、問題解決力、適応力、協働力を引き続き強化する。

### コメントと例

- 試験や評価など、本当の理解を示さなければならない場面に繰り返し出会う。技術力と対人スキルの両方を伸ばして備えること。
- 自分の考えを説明し、仲間と議論すると、理解の穴が見えてくることが多い。仲間との学びを優先すること。
- AI ツールはあなた固有の文脈を知らず、一般的な回答をしがちである。同じ環境にいる仲間は、より適切で正確な気づきを与えてくれる。
- AI は最もありそうな答えを生成しがちだが、仲間は別の視点や価値あるニュアンスを提供できる。品質の確認役として仲間を頼ること。

**✓ 良い例**

AI に「ソート関数はどうテストすればいい？」と聞く。いくつかのアイデアをもらい、試して、結果を仲間とレビューする。一緒にやり方を改善する。

**✗ 悪い例**

AI に関数を丸ごと書かせ、プロジェクトにコピペする。ピア評価でそれが何をしていて、なぜそうなのかを説明できない。信頼を失い、プロジェクトも落とす。

**✓ 良い例**

AI にパーサの設計を手伝ってもらう。そのロジックを仲間と一緒に順に追う。バグを2つ見つけ、一緒に書き直して、より良く、きれいで、完全に理解したものにする。

**✗ 悪い例**

プロジェクトの重要な部分を Copilot に生成させる。コンパイルは通るが、パイプの処理を説明できない。評価で根拠を示せず、プロジェクトを落とす。

## 第 V 章 Exercise 0: Planting Your First Seed

| 項目 | 内容 |
| --- | --- |
| 課題名 | `ft_garden_intro` |
| ディレクトリ | `ex0/` |
| 提出ファイル | `ft_garden_intro.py` |
| 使用可能 | `print()` |

複雑なガーデン管理システムを作る前に、Python プログラムの動作を理解する必要がある。

どの Python プログラムにも、実行が始まる場所である開始点が必要である。庭に最初の種を植えるようなものだ！

庭の植物の情報を表示する、最初の Python プログラムを作成すること。

**要件:**

- `python3 ft_garden_intro.py` で直接実行したときに動くプログラムを作成する。
- 特別なパターン `if __name__ == "__main__":` を使う。
- 次の植物情報を単純な変数に格納する: 名前（name）、高さ（height）、年齢（age）。
- `print()` を使って植物情報を表示する。
- 下の出力表示を真似ること。評価時に出力の厳密なチェックは行われない。

**実行例:**

```text
$> python3 ft_garden_intro.py
=== Welcome to My Garden ===
Plant: Rose
Height: 25cm
Age: 30 days

=== End of Program ===
```

> プログラムの開始と実行の仕組みを理解することは、クラスなどのオブジェクト指向の機能といった、より複雑な概念に進む前の基礎である。

**注:** この課題以降、このモジュールのすべての課題（および今後の Python プロジェクト）で、コードのテストに `if __name__ == "__main__":` ブロックを使ってよい。このパターンは使用可能な関数に明記されないが、プロジェクト全体を通じて使用できる。

> `if __name__ == "__main__":` の行がなぜ重要なのかを説明できなければならない。これは、今後のプロジェクトで扱うインポートの概念につながる。ただし、この良い習慣を今のうちに身につけておくことが重要である。

> `#!` で始まる特別な行から始まる Python ファイルがあることに気づいただろうか。この「シバン（shebang）」行が何をするのか、またスクリプトを直接実行可能にするうえでなぜ役立つのかを調べること。**評価では、このシバンを使うようにスクリプトをその場で修正するよう求められる。**

## 第 IX 章 Exercise 4: Garden Security System

| 項目 | 内容 |
| --- | --- |
| 課題名 | `ft_garden_security` |
| ディレクトリ | `ex4/` |
| 提出ファイル | `ft_garden_security.py` |
| 使用可能 | `print()`, `range()`, `round()` |

ガーデンの管理者はデータの整合性を懸念している。ボランティアが誤って不正な値（負の高さ、ありえない年齢）を設定し、植物データを壊してしまったことがある。機密性の高いデータを保護し、カプセル化する安全なシステムを作る必要がある。

**要件:**

- `Plant` クラスを改良し、データが壊れないように保護する。
- 植物データを制御された方法で変更する手段を用意する: `set_height()`, `set_age()`
- 植物データに安全にアクセスする手段を用意する: `get_height()`, `get_age()`
- 検証により、植物の高さが負にならないようにする。
- 検証により、植物の年齢が負にならないようにする。
- 不正な値が渡されたときはクラスからエラーメッセージを表示し、データを変更しないか、デフォルト値で植物を作成する。
- カプセル化を使う: 「protected」の慣例を使い（名前マングリングは使わない）、クラスの属性が直接使われないようにする。

データを保存する前に検証し、データの整合性を保証するシステムをどう作れるかを考えること。

**実行例:**

```text
$> python3 ft_garden_security.py
=== Garden Security System ===
Plant created: Rose: 15.0cm, 10 days old

Height updated: 25cm
Age updated: 30 days

Rose: Error, height can't be negative
Height update rejected
Rose: Error, age can't be negative
Age update rejected

Current state: Rose: 25.0cm, 30 days old
```

## 第 X 章 Exercise 5: Specialized Plant Types

| 項目 | 内容 |
| --- | --- |
| 課題名 | `ft_plant_types` |
| ディレクトリ | `ex5/` |
| 提出ファイル | `ft_plant_types.py` |
| 使用可能 | `super()`, `print()`, `range()`, `round()` |

ガーデンでは、花、木、野菜という異なる種類の植物を扱う必要が出てきた。それぞれの種類は固有の特徴を持ちつつ、親カテゴリから植物の共通機能を継承する。

**要件:**

- 共通の機能（名前、高さ、年齢）を持つ、前の課題の `Plant` クラスから始める。
- 特化した型 `Flower`、`Tree`、`Vegetable` を作成する。
- 各特化型は植物の基本機能を継承する。
- `Flower` には、`color` 属性と `bloom()` する機能が必要である。
- `Tree` には、`trunk_diameter` 属性と `produce_shade()` する機能が必要である。
- `Vegetable` には、`harvest_season` 属性と `nutritional_value` 属性が必要である。
- 特化した植物を作成するときは、新しいクラスの内部から `super()` を使って親のメソッドを呼び出す。これは `__init__()` を含むあらゆるメソッドに適用できる。
- 特化クラスで `show()` を呼び出すと、標準の `Plant` の出力に加えて、その植物固有の特徴を表示する。メソッドのオーバーライドでは、親の既存コードを再利用してよい。
- 各種類の植物のインスタンスを少なくとも1つ作成する。花を咲かせる。野菜の栄養価は 0 から始め、野菜の `age()` と `grow()` メソッドが呼ばれると増加するようにする。
- 特化型の間で、植物の共通コードを重複させない。
- 3つの新しいクラスの新しい属性を検証する必要はない。

> すべての植物の種類に共通する機能をどう扱っているだろうか。これらの共通機能を扱うために、異なるクラスで同じコードを繰り返さないことを推奨する。
