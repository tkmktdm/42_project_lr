## 絶対ルール

| ルール                                     | 内容                                                                                         |
| ------------------------------------------ | -------------------------------------------------------------------------------------------- |
| **PDF ファースト**                   | テスト・解説の生成前に必ず PDF を読む。推測で書かない                                        |
| **全関数一括生成**                   | PDF を読んだら実装済みかどうかに関わらず全関数分を生成する                                   |
| **支持がない場合は提出物に触らない** | `cursus/<課題名>/` 直下・`piscine/` 以下のファイルは読むだけ。編集・削除禁止             |
| **ビルド方式は自動判定**             | `Makefile` が存在する → `make`、存在しない → `cc` 直接。スクリプトが自動で切り替える |
| **テストはシェルスクリプト1本**      | `tests/test_<課題名>.sh` に全関数・全 exercise のテストを集約する                          |
| **日本語で回答**                     | ユーザーへの説明・レポートはすべて日本語                                                     |

## ビルド方式の自動判定ルール

課題ごとに `Makefile` の有無でビルド方式が変わる。スクリプト内で自動判定するため、Claude が手動で切り替える必要はない。

| 課題の種類                                   | Makefile | ビルド方式                  | 生成物       |
| -------------------------------------------- | -------- | --------------------------- | ------------ |
| libft・ft_printf・push_swap など             | あり     | `make` → `.a` にリンク | `libXXX.a` |
| get_next_line・minitalk など（単体ファイル） | なし     | `cc` 直接コンパイル       | 実行バイナリ |
| piscine（c00〜c09）                          | なし     | `cc` 直接コンパイル       | 実行バイナリ |

```bash
# スクリプト内の自動判定ロジック（compile_test 関数内に組み込み済み）
if [ -f "$PROJ_DIR/Makefile" ]; then
    # make でビルドして .a にリンク
    make -C "$PROJ_DIR" ${BONUS:+bonus} all
    cc ... "$PROJ_DIR/libXXX.a" -I "$PROJ_DIR" -o "$BIN"
else
    # cc で直接コンパイル
    cc -Wall -Wextra -Werror "$SRC" "$MAIN_C" -o "$BIN"
fi
```

## 作業フロー

```
STEP 1: PDF 読み込み → 全関数 / 全 exercise の仕様を一覧化
        ↓
STEP 2: ビルド方式を判定（Makefile の有無を確認）
        ↓
STEP 3: tests/<課題名>/test_<課題名>.sh を生成（全関数・全 exercise 分）
        ↓
STEP 4: solutions/<関数名 or exXX>.md を生成（全件分）
        ↓
        ── ここまでが「生成フェーズ」。以下は実行時に自動で行われる ──
        ↓
STEP 5: ビルド実行
          Makefile あり → make [bonus] が失敗したらスクリプト終了
          Makefile なし → 関数ごとに cc でコンパイル（失敗はその関数だけ FAIL）
        ↓
STEP 6: 関数 / exercise ごとにテスト実行
          ファイルが存在しない → [SKIP] して次へ
          存在する             → ①Norminette ②動作テスト ③標準関数比較 ④valgrind
        ↓
STEP 7: 結果レポート出力
```

## テストスクリプトの構造と書き方

### 基本方針

- **シェルスクリプト1本で完結**（`bash tests/test_<課題名>.sh` だけで動く）
- コンパイル用コードは **here-doc** でスクリプト内に直接書く（別 `.c` ファイルは作らない）
- **`Makefile` の有無を自動判定**してビルド方式を切り替える
- テストケースは **`# ===== カスタマイズここから =====`** ブロックに集約する
- 提出ファイルが存在しない関数・exercise は `[SKIP]` で飛ばす

---

### 汎用スクリプトテンプレート

このテンプレートを課題ごとにコピーして使う。
変更が必要な箇所は `# ★ 課題ごとに変える` コメントで示している。

```bash
#!/bin/bash
# =============================================================
# test_PROJ.sh — PROJ テストスクリプト          # ★ 課題名に変える
# 使い方: bash cursus/PROJ/tests/test_PROJ.sh
#
# 【自分でカスタマイズできる箇所】
#   - 各 test_<関数名>() 内の「カスタマイズここから/ここまで」ブロック
#   - テストケースの追加: run_test を1行追記するだけ
#   - bonus: BONUS=1 bash test_PROJ.sh
# =============================================================
```

| 項目         | piscine                              | 本科（cursus）                                            |

## Claude への動作指針

### テスト・解説の生成を依頼されたとき

1. 対象課題の PDF を読んで、**全関数 / 全 exercise** の仕様を一覧化する
2. **実装済みかどうかに関わらず全件分**のテスト関数・解説 md を生成する
3. テストスクリプトは **1 ファイルに全件を集約**する（`cursus/<課題名>/tests/test_<課題名>.sh`）
4. コンパイル用コードは **`compile_test` + here-doc** でスクリプト内に直接書く（別 `.c` ファイルは作らない）
5. テストケースは `# ===== カスタマイズここから/ここまで =====` で囲む
6. **`Makefile` の有無を確認**して `HAS_MAKEFILE` フラグをコメントで説明する（スクリプトは自動判定するので変更不要）
7. bonus 関数は `[ "$BONUS" != "1" ] && skip ... && return` で制御する
8. 解説は `cursus/<課題名>/solutions/<関数名>.md` に関数ごとに保存する
9. スクリプトに `chmod +x` を付与する

### テスト実行時の挙動

- Makefile あり・`make` 失敗 → ビルドエラーを表示してスクリプト全体を終了
- Makefile なし → 各関数で `cc` コンパイル。失敗はその関数だけ `[FAIL]`、次へ進む
- 提出ファイルが存在しない → `[SKIP]` して次へ（FAIL にしない）
- `SKIP` は失敗カウントに含めない

### やってはいけないこと

- 指示がないときに `cursus/<課題名>/` 直下・`piscine/` 以下の提出ファイルを編集する
- PDF を読まずに推測でテストや解説を書く
- テスト用の `.c` ファイルを別途作成する（`compile_test` + here-doc でスクリプト内に書く）
- 実装済みの関数・exercise だけテストを書いて未着手分を省略する
- Makefile がある課題で `make` をスキップして直接 `cc` でコンパイルする
- 解説の図解・NG パターン・チェックリストを省略する
